# Repo management review — 2026-07-02

Non-mod-code audit: website (`docs/`, `cloudflare-site/`), CI (`.github/workflows/`), and tooling (`scripts/`). All findings below were verified against the current tree; file:line citations point at the code in question.

## 1. Website updates

1. **Internal maintainer docs are publicly served from the GH Pages root.** `docs/` has no `.nojekyll`/exclusion, yet it hosts ~12 internal engineering files next to the player hub — `docs/COMPATIBILITY_CONTRACT.md`, `docs/MOD_OVERHAUL_EXECUTION_PLAN.md` (branch names, deferred backlog, phase plans), `docs/release-runbook.md`, `docs/self-hosted-runner-checklist.md`, `docs/VERSION_AND_RELEASE.md`, `docs/VERSION_BUMP_RULES.md`, `docs/MOD_LIFECYCLE_AND_LOGGING_CONTRACT.md`, `docs/MAINTAINER_VERSION_DRIFT_CHECKLIST.md`, `docs/SHARED_CODE_STRATEGY.md`, `docs/ATOMIC_SAVE_POLICY.md`, `docs/DOCKER_DOTNET_CONTAINER.md`, `docs/TranslationAudit_2026-05-24.md`. All of these are fetchable at `azraelgodking.github.io/SunhavenMod/...` even though nothing on the hub links to them. This is the biggest structural issue in `docs/` — using it as both the Pages source and the internal-docs folder.
2. **Stale mod count in search results.** `docs/search-index.json:6` — the "Arsenal comparison table" entry still reads `"Compare all 12 mods..."` / keyword `"twelve"`, while `docs/index.html:583` correctly says "thirteen" and there are 13 mods (GiftingAssistant shipped 2026-06-28). Confirmed by direct read — not fixed elsewhere.
3. **Stale `docsPagePath` for Haven's Birthright.** `scripts/mod-matrix.json:29` (and generated `docs/mod-matrix.json:24`) has `"docsPagePath": null` for `havensbirthright`, but a real page exists and is linked from `docs/index.html:154,569,587` at `RacialBonuses/RacialBonuces.html` (legacy folder name predating the mod-dir rename). Currently harmless since `docs/shared.js` doesn't consume the field, but it's stale ground-truth data.
4. **`cloudflare-site/AGENTS.md` is already out of date.** Its "Mod keys" list (`:84`) enumerates 12 keys and omits `giftingassistant`, even though `app.js:35,51` and `mod-page.js:24,100,121,136,300` already fully support it and `mods/giftingassistant.html` exists. The doc meant to keep the parallel site in sync drifted the moment the 13th mod shipped.
5. **Accessibility gap in `cloudflare-site/`.** `docs/index.html` has a skip-to-content link, `role="main"`, an `aria-live="polite"` status region, and ~20 `aria-*` attributes; `cloudflare-site/index.html` has none of that in its static markup and no skip-link. The parallel site is behind the baseline already established on the primary one.
6. **Running two full site implementations is a real, recurring tax.** Shipping GiftingAssistant required six independent hand-edited surfaces: `docs/index.html`, `docs/search-index.json`, `scripts/mod-matrix.json`/`docs/mod-matrix.json` on one side, and `cloudflare-site/app.js`, `cloudflare-site/mod-page.js`, `cloudflare-site/mods/giftingassistant.html` on the other — with no shared template. Findings #2 and #4 are direct symptoms.

No dead links, missing `alt` text, or leftover TODO/FIXME markers were found in either tree; stats/version/search-index data is otherwise well aligned across all 13 mods.

## 2. Workflow updates/changes

1. **Live bug — GiftingAssistant has no Discord announcement thumbnail.** `build-release-publish.yml:435-449`, the `notify_discord` job's `case "$PREFIX"` tag→mod-dir map, lists all 12 original mods but has no `GiftingAssistant)` branch. It falls through to `DIR=""`, and the `if [ -n "$DIR" ]` guard (`:450`) silently skips setting `url`. GiftingAssistant release announcements post without a thumbnail. GiftingAssistant *was* added to the `mod` dropdown at `:67` in the same file on 2026-06-28 — this second hardcoded list just wasn't updated in the same pass.
2. **`release-self-hosted-sunhaven-runner.yml` reimplements ~550 lines of `reusable-release-mod.yml` instead of calling it, and the duplication has already caused drift.** The documented 2026-05-24 fix for "Nexus zip missing after Thunderstore workspace reset" (stage the zip to `$RUNNER_TEMP/release-pkg`, restore before the Nexus step) exists in `reusable-release-mod.yml:279-289,384-390` but is entirely absent from the self-hosted workflow's equivalent `package_step`/`nexus_preflight` steps (no `RUNNER_TEMP` references at all). It currently avoids the bug only because this file happens to run Thunderstore *after* Nexus — an ordering coincidence, not a fix. Reordering steps here would silently reintroduce a bug already fixed once elsewhere.
3. **`update-stats.yml` has no concurrency group**, unlike `sync-mod-versions.yml:12-14` and `sync-cloudflare-site-mirror.yml:27-29`. Its hourly cron plus manual `workflow_dispatch` can race and fail the push to `docs/data/stats-cache.json` with a non-fast-forward error. One-line fix for consistency with sibling workflows.
4. **The `mod` choice dropdown is hand-duplicated across two workflow files** (`build-release-publish.yml:54-67`, `release-self-hosted-sunhaven-runner.yml:29-42`) with no automated check that they match `scripts/mod-matrix.json`, even though `reusable-mod-matrix-setup.yml:53-56` already enforces that `docs/mod-matrix.json` matches the source matrix. A similar drift-check on the dropdown enums would catch bugs like #1 automatically.
5. **Minor — `.github/workflow-templates/self-hosted-preflight-build-draft.yml` is dead weight.** Workflow-templates aren't executed, and it's stale (missing GiftingAssistant, predates `reusable-mod-matrix-setup.yml`). Could confuse a future maintainer into thinking it's live. Candidate for deletion.

Positive notes: `remove-stale-github-releases.yml`'s `!dry_run && !confirm_delete` hard-fail gate is a good defensive double-lock; Nexus retry/backoff and fail-closed logic in both release workflows correctly reflect prior incident lessons; release concurrency groups correctly use `cancel-in-progress: false` to avoid killing a live publish.

## 3. Script management

1. **Six orphaned one-off patch/scratch files, zero references anywhere in the repo:** `scripts/patch_almanac.json`, `scripts/patch_final.json`, `scripts/patch_thevault.json`, `scripts/apply_patch.ps1`, `scripts/patch_thevault.ps1`, `scripts/fix_small_mod_sweep.js`. No workflow, doc, or script references any of them — they're leftover ad hoc localization hotfixes and are indistinguishable from live tooling to a newcomer.
2. **`scripts/translate-phase1.log` is a committed, UTF-16LE console transcript (303 lines)** containing a maintainer's local Windows path (`F:\Repositories\SunhavenMod\...`). Nothing consumes it, and `.gitignore` has no `*.log` rule.
3. **No `scripts/README.md` exists** despite 33 files spread across PowerShell/Python/Node. Only ~7 are actually CI-invoked (`verify-version-consistency.py` + its `.ps1` wrapper, `validate-localization.ps1`, `stage-version-sync-files.py`, `set-versions-changelog.py`, `sync-docs-mod-matrix.js`, `fetch-stats.js`); the other ~15+ localization/audit scripts are local-only and never referenced by any workflow. Nothing distinguishes CI-critical from manual tools — the exact ambiguity that let #1/#2 go unnoticed.
4. **The ps1/py split is organized, not duplicated.** `verify-version-consistency.ps1` is a genuine thin wrapper delegating to `verify-version-consistency.py` ("Python verifier is the single source of truth"). The 3-language split is organized by job (Node → docs/stats sync, Python → version verification, PowerShell → build/localization pipeline), not forked logic. The real cost is contributor friction (three runtimes needed to touch different parts of the pipeline), not correctness risk.
5. **`scripts/.translation-cache.json` (400KB) is a legitimate, actively-used cache** (consumed by `fill-localization-languages.ps1:18`), but committing a large machine-generated JSON blob will keep growing repo size — worth gitignoring and regenerating on demand.

4. Move internal maintainer docs out of the publicly-served `docs/` GH Pages root (or add exclusion) so internal process content isn't unintentionally public.
5. Add `scripts/README.md` distinguishing CI-invoked vs. manual/local scripts, and fix the two small site data-drift bugs: stale "twelve" text in `docs/search-index.json:6` and stale `docsPagePath: null` for `havensbirthright` in `scripts/mod-matrix.json`.
